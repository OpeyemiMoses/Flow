# Provider evidence and assumptions

M0 provides interface definitions. Evidence below separates documented contracts, directly observed public responses, and behavior that still requires integration verification. The public reads on 6 November 2026 used no credentials and did not register wallets, request quotes, or initiate transfers.

## OutLayer

**Documented.** `POST /register` has random and deterministic modes. Random registration returns a one-time bearer credential. Deterministic registration derives identity from a NEAR account, seed and optional vault scope, and requires a NEAR authorization signature. The hosted registration operation does not declare a retry key. A local job alone cannot make a lost random registration response safe to retry. [Hosted OpenAPI](https://api.outlayer.ai/openapi.json) · [Agent Custody guide](https://app.outlayer.ai/docs/agent-custody)

**Documented.** The address API describes NEAR, shared EVM addresses including Base, and Solana. OutLayer broadcasts its native NEAR transfers and contract calls. The raw EVM and Solana operations return signatures for the caller to assemble and broadcast, subject to wallet policy. The native balance endpoint supports NEAR and provides a separate Intents balance mode. Use independent chain RPCs for EVM and Solana native balances. Cross-chain deposits into Intents credit a separate position. [Agent Custody guide](https://app.outlayer.ai/docs/agent-custody) · [Hosted OpenAPI](https://api.outlayer.ai/openapi.json)

**Observed.** A public GET of the hosted OpenAPI (`https://api.outlayer.ai/openapi.json`) returned HTTP 200 and identified version `0.1.0-alpha.4` (SHA-256 `d4a948b242cdd818033adc8f667309bfc85e49a163e1f12a7f433cb0e5200a93`). In M2 Phase 4, the official npm package `@outlayer/sdk@0.1.0-alpha.4` was also inspected offline (no credentials, no wallet creation). Key verified schema details in `0.1.0-alpha.4`:

- `POST /register` (`RegisterRequest` / `RegisterResponse`): supports anonymous `{}` and deterministic `{ account_id, pubkey, message, signature, seed, vault_id }` modes; returns `{ wallet_id, api_key, near_account_id, handoff_url, trial? }`.
- `GET /wallet/v1/address` (`AddressResponse`): accepts `chain` across 12 enum values (`near`, `ethereum`, `bitcoin`, `solana`, `arbitrum`, `base`, `optimism`, `polygon`, `avalanche`, `bsc`, `hyperevm`, `hood`); returns `{ wallet_id, chain, address, public_key, derivation_path, executor_account_id, vault_id, sub_path, gas_balance? }` where `executor_account_id` is `string | null` (equal to `address` on `chain=near` and `null` on non-NEAR chains).
- `GET /wallet/v1/policy` (`PolicyResponse`): returns `{ wallet_id, controller, frozen, policy?, rules?, approval?, capabilities?, authorized_key_hashes?, refund_addresses?, usage? }`. Newly registered wallets return `policy: "none"` (unrestricted in OutLayer until `store_wallet_policy` is called), and `policy` is omitted (`undefined`) if the coordinator cannot read or decrypt the on-chain policy.
- `POST /wallet/v1/auth-sign` (`AuthSignRequest` / `AuthSignResponse`): produces the signed message (`outlayer-wallet-auth:{account_id}:{seed_hex}:{vault_id}:{timestamp_ns}`) used for deterministic registration, `PUT /wallet/v1/api-key` credential rotation, and stateless `Authorization: Bearer near:{base64url}` authentication. [Hosted OpenAPI](https://api.outlayer.ai/openapi.json)

**Unverified (Requires Future Owner-Approved Live Compatibility Session).** Confirm live latency and rate-limit headers on `POST /register`, exact live behavior of `PUT /wallet/v1/api-key` (referenced in OpenAPI prose and `BearerAuth` security scheme, though not listed as a separate path item in `openapi.json` `0.1.0-alpha.4`), live `encrypt-policy` -> `sign-policy` -> `store_wallet_policy` controller provisioning on `controller.outlayer.near` / `vault.outlayer.near`, and live capabilities for each enabled asset. A wallet without a stored policy (`policy: "none"`) is documented as unrestricted; FLOW rejects `policy: "none"` and `policy: undefined`, requires `policy: "stored"` with default-deny rules before marking a wallet `ACTIVE`, and enforces `FLOW_EXECUTION=disabled` unconditionally across all evaluators. [Policy and recovery guide](https://app.outlayer.ai/docs/agent-custody) · [MPC vaults](https://app.outlayer.ai/docs/vaults)

## NEAR Intents 1Click

**Documented.** `GET /v0/tokens` lists provider asset IDs. `POST /v0/quote` supports a dry preview and a funded path with returned deposit instructions when committed. A fixed destination amount uses `EXACT_OUTPUT`. The payer sends on the origin chain and the recipient receives on the destination chain for the proposed demo. Deposit hash submission is optional. Status is polled by deposit address and, when needed, memo. Verify signed quote data, then independently verify the resulting delivery on-chain. [1Click OpenAPI](https://1click.chaindefuser.com/docs/v0/openapi.yaml) · [Swap types](https://docs.near-intents.org/integration/distribution-channels/1click-api/swap-types) · [Signature guide](https://docs.near-intents.org/integration/distribution-channels/1click-api/verify-quote-signature)

**Observed.** The hosted OpenAPI returned HTTP 200 in M0, resolving the earlier retrieval limitation. It identifies API version `0.1.10` with OpenAPI format `3.0.0`. The SHA-256 was `9a2e676682aa6dec6905c82f1b2cc0ec72eda97964369aa51ec35eb82ccac0a3`. The public token catalog returned HTTP 200 and included the following entries.
