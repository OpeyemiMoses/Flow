# FLOW Milestone 2 Phase 3 — Fixture-Backed Wallet Provisioning Worker & Local Onboarding Integration

**Status:** Complete (Fixture-Backed Worker & Local Onboarding Integration Verified) · Live OutLayer Provisioning Disabled (`FLOW_EXECUTION=disabled`)

---

## 1. Scope & Implementation Summary

Milestone 2 Phase 3 implements the durable local wallet provisioning worker, simulated OutLayer multi-wallet fixture provider, and transactional onboarding/business job enqueue while preserving all M0, M1, M1.2, and M2 Phase 2.2 security invariants:

1. **Durable Wallet Provisioning Worker (`src/server/custody/provisioning-worker.ts`):**
   - Implements `WalletProvisioningWorker` with lifecycle management (`start`, `stop`, `runOnce`, `processAccountJob`, `getDiagnostics`, `computeBackoffDelayMs`), bounded retries (`attempts < max_attempts`), exponential backoff, concurrency controls (`maxConcurrency`), and graceful shutdown awaiting all in-flight tasks.
   - Executes a 3-stage pipeline (`SETUP_PENDING`/`REGISTERED` → `PROVISIONING`/`PROVISIONED` → `ACTIVE`/`ACTIVE`) using short atomic PostgreSQL transactions. **Zero database transactions or row locks remain open during external provider network calls (`register`, `getAddress`, `getPolicy`).**

2. **Immediate Credential Persistence & Resumable Crash Recovery without Re-Registration:**
   - Immediately after a simulated `/register` call succeeds, the worker encrypts the one-time `wk_...` bearer key into a versioned AES-256-GCM envelope (`src/foundation/crypto-envelope.ts`), scrubs any bearer key parameters from `handoff_url` (`scrubHandoffUrl`), and commits Stage 1 (`persistRegisteredWallet`) before any address derivation or policy query.
   - If a worker crashes after Stage 1 (`REGISTERED` / `SETUP_PENDING`) or Stage 2 (`PROVISIONED` / `PROVISIONING`), `reconcileCrashedJobs` clears the expired lease while preserving the job stage, and the next worker decrypts the persisted credential from `flow.wallets` and resumes Stage 2/Stage 3 without invoking `/register` again.
   - If a worker crashes after `recordJobDispatch` (`SUBMITTED`) before Stage 1 completes, or if `/register` fails with a timeout/5xx/network error, the job is quarantined to `UNKNOWN` (`POST_DISPATCH_AMBIGUOUS`) and never automatically re-registered.

3. **Transactional Personal Onboarding & Business Creation Job Enqueue (`src/server/accounts.ts`):**
   - `onboard` (`/api/onboarding/complete`) and `createBusiness` (`POST /api/accounts`) atomically enqueue an idempotent `PENDING` job in `flow.wallet_provisioning_jobs` via `ensureProvisioningJobForAccount(tx, accountId, accountProvisioningKey(accountId))` inside the account creation transaction.
   - Account creation transactions never call external providers or block on wallet registration.
   - Personal and business accounts receive strictly separate provisioning jobs, wallet rows, provider wallet IDs, encrypted credentials, and multi-chain addresses.

4. **Tightened State Transitions & Unforgeable Adapter Policy Provenance (`src/domain/custody.ts`, `src/server/custody/job-repository.ts`):**
   - `persistRegisteredWallet` requires `job.status === "SUBMITTED"` and `job.dispatched_at IS NOT NULL`.
   - `activateWalletIfReady` requires `wallet.status === "PROVISIONING"` and `job.status IN ("PROVISIONED", "POLICY_VERIFYING", "LEASED")`, rejecting direct activation from `SETUP_PENDING`, `PENDING`, `SUBMITTED`, or `REGISTERED` with `FlowError("INVALID_STATE_TRANSITION")`.
   - `OutLayerAdapter.getPolicy()` mints an unforgeable HMAC-SHA256 provenance token (`mintTrustedAdapterPolicyEvidence`) bound to a process-private `Symbol("flow.outlayer.adapter.policy.provenance")`. `verifyCustodyPolicyEvidence()` rejects both caller-supplied strings and caller-fabricated plain objects lacking adapter provenance, and requires non-empty `rules` with `rules.defaultAction === "DENY"` and `transferSigning !== "enabled"`.

5. **Strengthened Chain-Specific Address Validation (`src/domain/custody.ts`):**
   - **Solana:** `decodeBase58` decodes the Base58 string and verifies the decoded byte array is **exactly 32 bytes** and non-zero.
   - **EVM (Base / Ethereum):** Pure Keccak-256 (`keccak256Hex`) + `toEip55ChecksumAddress` enforces EIP-55 mixed-case checksums and rejects the all-zero burn address (`0x0000000000000000000000000000000000000000`).
   - **NEAR:** Validates 64-hex lowercase non-zero implicit accounts and named accounts requiring at least one dot separator (`>= 2` labels) with no leading, trailing, or consecutive `-`, `_`, or `.`.

6. **Live OutLayer Prohibition & Execution Guard (`FLOW_EXECUTION=disabled`):**
   - Whenever `FLOW_EXECUTION=disabled`, `OutLayerAdapter` verifies that `this.baseUrl` targets a local loopback hostname (`127.0.0.1`, `localhost`, `[::1]`) and immediately throws `FlowError("INVALID_CONFIGURATION")` before opening any network socket to a remote host (`https://api.outlayer.ai`).
   - `provisioningComplete` (`status === "ACTIVE"`) remains strictly decoupled from `fundsReady` (`false`), `canReceiveFunds` (`false`), and `canSignTransfers` (`false`).
