## Architecture and dependencies

- The App Router shell is the web entry point. Server configuration and diagnostics are separate from type-only contracts for wallet custody, routing and chain evidence. Source and destination each carry their own network, asset and address. NEAR to Base is the initial demo configuration.
- The initial database migration creates the `flow` namespace and grants the environment's app role `USAGE`. Prisma owns the migration history. The `pg` driver supplies the bounded readiness read while domain models and Prisma Client generation are deferred.
- Startup requires an explicit environment and disabled financial execution. Each environment has its own database name and runtime and migration roles. Local and test use loopback. Staging and production require verified TLS and separate migration credentials. Health responses and logs omit connection details.
- Minimum settlement accounting must be in place before an M6 payment can complete. Final chain evidence, the balanced journal and payment completion must commit atomically. Atomic spending reservations must precede any actual user-funded outgoing transfer, including any future use of an M4 adapter.
- Development and production build use Next.js's Webpack mode. Turbopack's CSS worker failed to bind an internal port in this workspace, including on the approved retry. Webpack compiled and served Tailwind CSS in the production smoke test. [Next.js bundler options](https://nextjs.org/docs/app/getting-started/installation#manual-installation)

### Migration status

The native server ran PostgreSQL 17.11 on loopback. Docker and `psql` were absent from the available host. The default sandbox also blocked PostgreSQL's shared-memory allocation. The approved native run used a checksum-verified PostgreSQL distribution under `work/`. It used the same bootstrap SQL statements as the container workflow, with generated passwords passed through a PostgreSQL client.

- On the fresh `flow_test` database, the pre-migration readiness check returned `DATABASE_NOT_READY`. The first deploy applied `20261106000000_flow_namespace` and subsequent deploys reported no pending migrations.
- Applied the migration to the separate `flow_local` database and confirmed runtime readiness there. Prisma reported both databases up to date. A direct query of the test migration table returned one completed, active row for the baseline.
- The runtime role passed the namespace and identity check. PostgreSQL denied it schema DDL and denied the test app role access to `flow_local`. The server was stopped after verification.

### Security and integration evidence

Unit checks exercised missing configuration, cross-environment and cross-role URL rejection, unsafe hosts and TLS settings, public variable rejection, and redaction of structured fields and credential-bearing strings. A driver regression test checked that PostgreSQL's URI parsing preserves explicit certificate verification. The HTTP smoke check confirmed that the generated test connection strings and passwords were absent from responses and logs. A separate scan found none of the disposable credentials in the 36 project files, 21 client assets or production smoke log. The stopped cluster and its temporary credentials were removed. npm allows install scripts for the two pinned Prisma packages and rejects unreviewed dependency scripts.

Read-only requests returned HTTP 200 for OutLayer's hosted OpenAPI, the 1Click OpenAPI, and the 1Click catalog. The hosted versions were OutLayer `0.1.0-alpha.4` and 1Click `0.1.10`. The catalog listed both demo assets. The source URLs, schema digests, and open provider questions are recorded in `docs/integrations.md`. The evidence covers contracts and catalog data. Wallet provisioning, routing, payments, and account authentication are outside this milestone.
