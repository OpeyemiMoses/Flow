## 2. Preflight Architectural Corrections & Implementation Details

### 2.1 Audit & Column-Level Privilege Isolation on `flow.wallets`

- **Vulnerability Addressed:** In earlier milestones, the runtime web application role (`app_role`) had table-level `SELECT` on `flow.wallets`, which theoretically allowed an application-level SQL injection or direct query to inspect `encrypted_credential`, `key_id`, or `key_digest`.
- **Database Hardening (`prisma/migrations/20261107030000_m253_preflight_corrections/migration.sql`):**
  1. Revoked table-level `SELECT ON flow.wallets FROM app_role`.
  2. Granted column-level `SELECT (id, account_id, provider, environment, provider_wallet_id, near_account_id, status, policy_state, controller_account_id, handoff_url, created_at, updated_at) ON flow.wallets TO app_role`.
  3. Created `flow.wallet_public_projections` view containing strictly the 12 non-secret columns, granted to `app_role`, `worker_role`, and `operator_role`.
- **Verification:** Direct SQL queries by `app_role` requesting `encrypted_credential`, `key_id`, `key_digest`, or `SELECT *` from `flow.wallets` fail with PostgreSQL error code `42501` (`insufficient_privilege`).

### 2.2 Public Wallet Projection Compatibility

- Updated `getAccountWalletPublicProjection` in `src/server/custody/job-repository.ts` to query `flow.wallet_public_projections`.
- All user-facing onboarding flows, account dashboards, and wallet status checks continue functioning without code breakage or schema mismatch.

### 2.3 Permanent Durability of Provider Compatibility Authorizations

- **Durability Invariants:**
  1. `REVOKE DELETE ON flow.provider_compatibility_authorizations FROM app_role, worker_role, operator_role`.
  2. Implemented PostgreSQL BEFORE UPDATE OR DELETE trigger `flow.prevent_compatibility_authorization_tampering()`:
     - Blocks all `DELETE` attempts by non-migrator roles (`42501`).
     - Blocks resetting `status` back to `'AUTHORIZED'` from `'CLAIMED'`, `'CONSUMED'`, `'QUARANTINED'`, or `'EXPIRED'` (`23514`).
     - Blocks mutating `status`, `account_id`, `singleton_scope`, or `max_registrations` once `'CONSUMED'` or `'QUARANTINED'` (`23514`).
     - Blocks decrementing `registrations_attempted` or `registrations_completed` counters (`23514`).
  3. Preserved unique index on `singleton_scope = 'GLOBAL_TESTNET_REHEARSAL'` (`23505`).

### 2.4 Anonymous Registration Lifecycle Reconciliation

- **Lifecycle Distinction:** An OutLayer anonymous registration on testnet produces `{ wallet_id, api_key, near_account_id }` and an initial policy state of `"none"`. It does NOT have an on-chain controller policy (`"stored"`).
- **Hardening:**
  1. Added `inspectCustodyPolicyEvidence(evidence, expectedProviderWalletId)` in `src/domain/custody.ts` to inspect policy evidence without throwing on `policy: "none"`.
  2. Added `recordRegisteredWalletWithoutPolicy(db, jobId, fencingToken, walletId, policyState)` in `src/server/custody/job-repository.ts`:
     - Leaves wallet `status = 'PROVISIONING'` (recorded as registered).
     - Job status transitions to `PROVISIONED` with `outcome: "registered"`.
     - `fundsReady` remains `false`.
     - Capabilities remain strictly `canReceiveFunds: false` and `canSignTransfers: false`.
     - Wallet is NOT marked `ACTIVE`.

### 2.5 Environment Variable Reconciliation

- Standardized on `FLOW_OUTLAYER_API_URL` (canonical default: `https://api.outlayer.ai`, testnet: `https://testnet-api.outlayer.ai`).
- Updated `readWalletConfig` in `src/foundation/wallet-environment.ts` to accept legacy/alternate variable names `OUTLAYER_BASE_URL` and `OUTLAYER_API_URL` as fallbacks.
- Verified that OutLayer `/register` for anonymous wallets requires NO upstream `OUTLAYER_API_KEY` or `Authorization` header.

### 2.6 Privileged Authorization Identity Derivation

- Privileged custody actions (`createCompatibilityAuthorization`, `createCustodyRecoveryApproval`, `enrollCustodyOperator`) now derive operator identity from `deriveOperatorContext(db, input, requiredRole)`.
- Returns `AuthenticatedOperatorContext` verifying:
  1. User is registered in `flow.auth_users`.
  2. Active authority and required role in `flow.custody_operators`.
  3. If session token is provided, active non-expired session bound to the user in `flow.auth_sessions`.
- Unprivileged accounts or callers lacking operator authority fail immediately with `CUSTODY_OPERATOR_AUTHORIZATION_ERROR` or `CUSTODY_OPERATOR_AUTHENTICATION_REQUIRED`.

### 2.7 Deterministic One-Time Rehearsal Command

- Implemented `scripts/rehearse-testnet-registration.ts` (invoked via `npm run rehearse:testnet`).
- Supports `--dry-run`, `--account-id`, `--operator-id`, and `--help`.
- Validates preflight conditions before initiating outbound network calls:
  - `FLOW_ENV`: local or test.
  - `FLOW_EXECUTION`: strictly `disabled`.
  - `FLOW_PROVIDER_COMPATIBILITY_MODE`: `authorized`.
  - Coordinator URL: verified against `https://testnet-api.outlayer.ai`.
  - Account: isolated personal account with no existing active wallet.
  - Authorization: active `flow.provider_compatibility_authorizations` singleton record.
