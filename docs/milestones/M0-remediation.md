## Security and architecture

- **Credential boundary.** The web dotenv template has only `FLOW_ENV`, `FLOW_EXECUTION` and the app role URL. Bootstrap passwords stay in the operator command; Prisma accepts only the migrator URL. In a clean process, Next.js's own dotenv loader loaded exactly those three web settings. Real `next start` exited 1 when given an inherited migration URL, administrator password, or migrator password. It also exited 1 with a migration URL in `.env.local`. A real `next build` refused an inherited administrator password. No tested secret values appeared in the failure output. Prisma ignored the web dotenv file and refused a process containing both URLs. See [Next.js dotenv precedence](https://nextjs.org/docs/app/guides/environment-variables#environment-variable-load-order), [Prisma configuration](https://www.prisma.io/docs/orm/v7/reference/prisma-config-reference#using-environment-variables), and [Compose interpolation](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/#ways-to-set-variables-with-interpolation).
- **Database boundary.** The application identity cannot create a schema, create tables in `flow` or `public`, read Prisma migration history, or connect to the other local FLOW database. PostgreSQL returned SQLSTATE `42501` for each. Readiness rejected the empty database before migration and each temporary elevation in a live cluster: the `CREATEDB` role attribute, membership in `pg_read_all_data`, database `CREATE` and `CREATE` on the public schema. It returned to ready after revocation. Prisma verifies migration history under the migrator role.
- **Financial safeguards.** `FLOW_EXECUTION=disabled` is mandatory; a real `next start` with `FLOW_EXECUTION=live` exited 1. [Provider interfaces](../../src/domain/providers.ts#L48) still carry independent assets and networks on the source and destination, and keep custody, routing and chain evidence separate. NEAR to Base remains the first demo. Minimum settlement accounting precedes M6 payment completion; atomic reservations precede any user-funded outgoing transfer. No authentication, provisioning, routing calls or financial execution were added.

## Remaining gates

- **GitHub Actions and Docker.** The local YAML and shell checks do not execute a hosted runner or the Docker image entrypoint. Confirm a hosted run against the reviewed commit. The native PostgreSQL evidence verifies the SQL, Prisma migration and app permissions.
- **Deployment.** Verify staging and production TLS, grants, and separate OS or deployment identities in the actual environment. Local credential isolation was verified for the documented process inputs. An account with access to the operator's processes, secret store or Docker daemon is outside that boundary. Redaction covers the tested formats; keep raw credential-bearing payloads out of logs.
- **Providers and milestones.** The integration assumptions in [provider evidence](../integrations.md) still apply. Live provider behavior and custody recovery require their later gates. M0 remains pending review; M1 requires explicit approval.
