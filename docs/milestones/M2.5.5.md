## 2. Technical Implementation Details

### 2.1 Job State Invariant Resolution (`isJobPristineInitial`)

In Phase 5.4, the rehearsal CLI rejected any account having ANY row in `flow.wallet_provisioning_jobs`. However, standard personal onboarding (`createPersonalAccount` in `src/server/accounts.ts`) calls `ensureProvisioningJobForAccount`, creating an initial `PENDING` job with `fencing_token = 0`, `attempts = 0`, `dispatched_at IS NULL`.

Phase 5.5 introduces `isJobPristineInitial`:

- **Clean Initial State (Accepted):** `status === 'PENDING'`, `fencingToken === 0`, `dispatchedAt === null`, `attempts === 0`, `failureClassification === null`, and unleased. This represents a pristine unstarted job from onboarding that has never been touched by any worker.
- **In-Flight or Terminal State (Strictly Rejected):** Any non-`PENDING` status (`LEASED`, `SUBMITTED`, `REGISTERED`, `PROVISIONED`, `UNKNOWN`, `FAILED`), non-zero fencing token, non-zero attempts, active lease, or non-null dispatch timestamp is rejected with `INVALID_CONFIGURATION` (or `ACCOUNT_HAS_IN_FLIGHT_OR_TERMINAL_JOB` in dry-run).
- **Wallet Presence (Strictly Rejected):** Any account with 1 or more records in `flow.wallets` (regardless of wallet status) is rejected.

### 2.2 Authorized Account Preparation CLI (`scripts/prepare-testnet-account.ts`)

- Provides an idempotent, authorized operational script `scripts/prepare-testnet-account.ts` (`npm run prepare:testnet-account`).
- Requires `FLOW_EXECUTION=disabled` and `FLOW_ENV` in `['local', 'test']`.
- Verifies operator authentication and privileges (`SECURITY_OFFICER` or `CUSTODY_OPERATOR`) using `deriveOperatorContext` via `FLOW_OPERATOR_DATABASE_URL`.
- Uses `app_role` (`FLOW_DATABASE_URL`) to transactionally provision:
  1. `flow.auth_users` record for the designated test user.
  2. `flow.users` application user.
  3. `flow.accounts` personal account (`kind: 'PERSONAL'`).
  4. `flow.wallet_provisioning_jobs` pristine initial `PENDING` job via `ensureProvisioningJobForAccount`.
  5. `flow.security_audit_events` audit event (`kind: 'personal-created'`).
- Uses `operator_role` (`FLOW_OPERATOR_DATABASE_URL`) to verify that the account has 0 wallets and exactly 1 pristine initial job.
- Emits sanitized CLI output and exit codes.

### 2.3 CLI Error Sanitization (`formatSanitizedCliError`)

- Removed `(error as Error).message` from `scripts/rehearse-testnet-registration.ts` and `scripts/prepare-testnet-account.ts`.
- Mapped all `FlowError` codes (`INVALID_CONFIGURATION`, `CUSTODY_OPERATOR_AUTHENTICATION_REQUIRED`, `CUSTODY_OPERATOR_AUTHORIZATION_ERROR`, `CUSTODY_REGISTRATION_BUDGET_EXCEEDED`, `PROVIDER_COMPATIBILITY_UNAUTHORIZED`, `PROVIDER_UNAVAILABLE`, `INCOMPLETE_WALLET_PROVISIONING`, `DATABASE_UNAVAILABLE`) to predefined, sanitized diagnostic descriptions.
- Mapped all untyped/unexpected errors to code `UNEXPECTED_ERROR` with a generic diagnostic directing operators to secure audit logs.
- Prevents database connection strings, SQL query fragments, upstream headers, or file paths from leaking to stdout/stderr.

When the repository owner grants explicit approval for the first OutLayer testnet wallet registration:

1. **Step 1 — Create Single-Use Compatibility Authorization:**
   ```bash
   npm run authorize:testnet -- \
     --account-id <ACCOUNT_ID> \
     --operator-id <OPERATOR_ID> \
     --session-token-file /path/to/operator-session.token
   ```
2. **Step 2 — Verify Dry-Run Passes with Authorization Active:**
   ```bash
   npm run rehearse:testnet -- \
     --dry-run \
     --account-id <ACCOUNT_ID> \
     --operator-id <OPERATOR_ID> \
     --session-token-file /path/to/operator-session.token
   ```
   (Must report: `prerequisitesSatisfied: true`, `Exit Code: 0`, `ZERO database writes performed`.)
3. **Step 3 — Execute Deterministic One-Time Live Rehearsal:**
   ```bash
   npm run rehearse:testnet -- \
     --account-id <ACCOUNT_ID> \
     --operator-id <OPERATOR_ID> \
     --session-token-file /path/to/operator-session.token
   ```
4. **Step 4 — Verify Post-Execution Safety Invariants:**
   - Provider Wallet ID and encrypted credential saved atomically in `flow.wallets`.
   - `fundsReady: false` and `eligibleForDeposits: false`.
   - `registrations_attempted: 1` and `registrations_completed: 1`.
   - Attempting a second execution is blocked by `CUSTODY_REGISTRATION_BUDGET_EXCEEDED`.
